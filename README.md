# Baltimera

Сайт Baltimera на Next.js 16 (App Router). Дизайн перенесён из статической вёрстки
дизайнера один в один: те же секции, та же типографика, те же анимации.

## Запуск

    bun install
    bun run dev          # разработка
    bun run build        # продакшн-сборка (страница пре-рендерится статически)
    bun run start        # локальный продакшн-сервер

## Структура

| Путь | Что там |
|---|---|
| `app/layout.tsx` | html/body, метаданные, preload шрифта, скрипт заставки, контекст диалогов |
| `app/page.tsx` | порядок секций одной страницы |
| `app/globals.css` | стилевой файл дизайнера без правок, кроме путей к шрифтам и фоновой картинке |
| `components/` | секции страницы: серверные компоненты дают разметку, клиентские — интерактив |
| `lib/photos.ts`, `lib/nav.ts` | данные фотографий и навигации |
| `lib/ui.tsx` | лайтбокс фотографий и информационные диалоги (политика, языки) |
| `lib/panel-viewer.ts` | порт `panel-3d.js`: three.js r170, геометрия из `public/data/panel-cad-v16.json` |
| `lib/intro-boot.ts` | скрипт первого кадра: заставка первого посещения и подготовка появления секций |
| `components/site-effects.tsx` | порт `app.js`: появление при скролле, параллакс, аккордеон на телефоне, высота мобильного первого экрана |
| `public/images`, `public/fonts`, `public/data` | webp, woff и CAD-геометрия |
| `dist/`, `generate.py`, `source-assets/` | замороженная сборка дизайнера — референс для сравнения, сайт её не использует. `dist/` в гит не попадает (в `.gitignore`), он остаётся только локально для скриптов сравнения |
| `scripts/*.cjs` | служебные скрипты сравнения Next-версии с `dist/` |

## Что сделано для скорости

- Страница пре-рендерится статически; контент не зависит от клиентского JS.
- Изображения идут через `next/image`: AVIF с фолбэком на WebP, адаптивные размеры,
  ленивая загрузка; первый экран остаётся `<picture>` с отдельным кадром для телефона.
- three.js и CAD-модель (600 КБ JSON) грузятся отдельным чанком и только когда секция
  приблизилась к экрану или посетитель нажал «Рассмотреть в 3D».
- Шрифт Inter с preload, ассеты отдаются с длинным `Cache-Control`.
- Никаких UI-библиотек и CSS-фреймворков: дизайнерский CSS подключён как есть.

## Что не настраивалось

- SEO и GEO: ничего не добавлялось. `title`, `description`, `og:*` и иконка перенесены
  из исходной вёрстки как были.
- Отправка формы: как и в прототипе, данные проверяются локально и никуда не уходят.
  Подключение бэкенда — отдельная задача.

## Проверка соответствия оригиналу

Скрипты требуют установленный Chrome (путь в начале файла) и `puppeteer-core` из devDependencies.

    node scripts/serve-dist.cjs dist 3222     # отдать исходную сборку
    bun run start                             # собрать и запустить Next на 3111
    node scripts/capture-parity.cjs           # полные скриншоты 1440/900/390 в .verify/
    node scripts/pixel-diff.cjs               # попиксельное сравнение и карта отличий
    node scripts/behavior-parity.cjs          # одинаковые клики по обеим версиям, снимки DOM
    node scripts/probe-parity.cjs             # подсветка меню и 3D при прокрутке
    node scripts/check-intro.cjs              # заставка первого посещения
    node scripts/check-info-dialogs.cjs       # диалоги языков и политики
    node scripts/check-live.cjs               # проверка задеплоенного сайта (ошибки, 3D, форма, скриншоты)

Результат последнего прогона: высоты страницы совпадают до пикселя на всех трёх ширинах
(6894 / 6398 / 9297), рендер 3D-канваса и первого экрана — 0% отличий, все шаги
интерактивности совпадают. Отличия остаются только внутри фотографий: их пересжимает
оптимизатор Next.

## Известные отличия от dist/

- Фотографии отдаются пересжатыми (AVIF q75 вместо файлов дизайнера): визуально то же
  самое, мелкая фактура древесины чуть мягче, вес в 3–6 раз меньше.
- Старая сборка `dist/` и `generate.py` оставлены как референс. Если они больше не нужны,
  их можно удалить — сайт их не использует.

## Если понадобится статический хостинг

Сейчас проект собирается как обычное Next-приложение (страница пре-рендерится, но нужен
Node-рантайм или Vercel) — на этом работает оптимизатор изображений. Если сайт придётся
выкладывать как статическую папку (`output: 'export'`), `next/image` перестанет
оптимизировать картинки и они уедут в исходном размере: тогда лучше вернуть `srcset`
из `dist/` или отдать фото через CDN.
